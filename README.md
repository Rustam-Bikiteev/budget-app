# Бюджет

Веб-приложение для бюджета между выплатами. Облачный режим `/` хранит общий
семейный бюджет в Supabase. `/free/` хранит личный бюджет в браузере без аккаунта.
Обе версии работают на GitHub Pages без сборки и отдельного сервера приложения.

## Работа с бюджетом

В облачной версии параметры открываются явным действием «Изменить доход и
накопления», графики находятся в «Аналитике». Отложенные покупки в обеих версиях
называются «Будущие покупки».

«План» в таблице задаёте вы. «Выделено на траты» в облачной сводке включает план
и перерасходы: для каждой траты берётся большая из сумм плана и факта.
«Осталось без перерасходов» складывает положительные остатки отдельных трат;
таблица показывает план минус факт, включая отрицательные остатки. Поэтому эти
суммы могут отличаться. `/free/` сохраняет свою сводку: «Остаток» равен
доходу за вычетом обязательных платежей, накоплений и фактических трат.

При записи виден статус «Сохраняется», после завершения всей операции
«Сохранено», при отказе «Не удалось сохранить». Он остаётся до следующей записи.
После ошибки правки полей можно повторить: введённый текст остаётся в поле.
Статус относится к записи бюджета, а не к резервной копии файла.
Первый запуск `/free/` показывает три шага; подробности периодов, расчётов,
копий и установки раскрываются отдельно. Сведения о локальном хранении и
необходимости копии видны сразу.

Период длится с 10-го по 24-е либо с 25-го по 9-е следующего месяца.
С 1-го по 9-е число открывается второй период прошлого месяца.

## Облачная версия

Для `/` нужна новая [семейная схема Supabase](docs/ARCHITECTURE.md#облачная-схема-и-rpc-этап-4а).
У каждой семьи свои данные, категории и роли. Новая семья начинает с категории
«Общие». У обязательной траты можно включить галочку «Резерв». Переименование
сохраняет этот признак. Нажатие на красное «Осталось» открывает покрытие
перерасхода из накоплений или резерва.

Супруги входят разными аккаунтами Supabase Auth и выбирают один семейный бюджет.
После регистрации с подтверждением почты нужно перейти по ссылке из письма и войти.
Без семьи приложение предлагает создать бюджет или присоединиться по приглашению;
при нескольких семьях показывает выбор. В «Аккаунте» видны название и ваша роль.
Владелец меняет название семьи и категории, создаёт одноразовую ссылку на сутки.
Ссылку нужно скопировать вручную и передать партнёру; приложение не отправляет письма
с приглашениями. Приглашение сохраняется до входа. Управления удалением семей и участников нет.

Если данные изменились на другом устройстве, правка отклоняется. «Обновить данные»
перечитывает бюджет и сохраняет изменённые поля для явного повтора; неизменённые
поля показывают свежие значения. Черновик удалённой записи остаётся доступен для копирования.

В «Потратил вне плана» источник выбирается сразу: свободные, отложенные или непредвиденные.
Плюс открывает новую запись с отдельными планом и фактом. Галочка «Вне плана»
показывает выбор источника: сумма добавляется к плану и факту траты;
отложенные или резерв уменьшаются на ту же сумму.
Для этих двух источников нужен достаточный остаток. Свободные можно превысить: появится дефицит.

Протяжка вниз от начала экрана обновляет данные текущего спринта.
Во время ввода и в открытых диалогах жест не срабатывает.

## Общедоступная версия (`free/`)

[Открыть бесплатную версию](https://rustam-bikiteev.github.io/budget-app/free/)

- без регистрации и сервера: данные в IndexedDB браузера пользователя
- категории настраиваются (название + цвет)
- составные операции (перенос в бэклог, копирование плана, восстановление) — одной транзакцией
- `navigator.storage.persist()` запрашивает защиту от автоматического вытеснения.
  Запрос может быть отклонён браузером; проверяйте фактический
  статус в настройках. Резервная копия нужна в любом случае.
- ручную очистку данных сайта запретить нельзя, поэтому защита — резервные копии:
  - «Сохранить копию» (JSON; на телефоне через «Поделиться»)
  - автосохранение в выбранный файл после каждой правки (Chrome / Edge на компьютере)
  - напоминание, если копии нет больше 3 дней
  - «Восстановить из файла» с проверкой файла и откатом к прежним данным
- `free/sw.js` — офлайн-кэш оболочки (network-first)
- при первом запуске есть справка по периодам, установке и хранению данных
- версия и ссылка для сообщения об ошибке доступны в настройках
- ручной экспорт требует подтверждения, что файл сохранён вне браузера;
  успешная автозапись подтверждается только после закрытия файла

## Локальный запуск

Из корня проекта запустите `node tests/e2e/server.cjs` и откройте нужную страницу:

- [Локальная версия](http://127.0.0.1:8138/free/) использует IndexedDB на локальном адресе.
- [Облачный интерфейс с демоданными](http://127.0.0.1:8138/design/preview.html?theme=lilac)
  хранит изменения в памяти до перезагрузки.

На корневой странице `/` включено подключение Supabase из `index.html`.
Для ручных проверок входа и облачных записей укажите URL и публичный ключ
отдельного тестового проекта. Перед E2E остановите сервер ручного просмотра:
Playwright поднимает свой на том же порту.

## Проверки

Полный набор на Node.js 24.14.1:

```powershell
npm ci
npx playwright install chromium
npm run check
npm run package:pages
```

`npm test` запускает регрессии, включая исполняемые SQL/RLS-тесты
в PGlite. `npm run test:e2e` проверяет оба режима в браузере. Браузерные тесты
блокируют внешние HTTP и WebSocket. Корневая страница использует подставной Supabase SDK.
На Linux системные зависимости устанавливаются через
`npx playwright install --with-deps chromium`. Если Chromium недоступен, в PowerShell
можно запустить локальный набор с установленным Chrome:
`$env:BUDGET_E2E_CHANNEL='chrome'; npm run check`.
Отчёт браузера открывается через `npx playwright show-report`.

Сценарии и пределы покрытия перечислены в [индексе тестов](docs/INDEX.md#тесты).
Перед выпуском сверьтесь с [чек-листом](docs/RELEASE_REVIEW.md#чек-лист-выпуска)
и [проверками на телефонах](docs/FREE_PILOT.md#проверка-на-реальных-устройствах).

### Приёмка изменений интерфейса

1. Запишите действие пользователя и ожидаемый результат. Например, после отказа
   записи сумма остаётся в поле, виден статус ошибки, ввод можно повторить.
2. В браузере повторите сценарий на тестовых данных. Для общих компонентов
   пройдите его в `/free/` и облачном интерфейсе на 320 и 390 px и на desktop.
   Проверьте касание, фокус с клавиатуры и состояния, которые затрагивает правка.
3. Сверьте видимый результат с ожиданием. Для регрессии добавьте проверку в E2E,
   а при изменении вёрстки сохраните скриншот в `test-results/`.
   В результате укажите, где проверили сценарий и какие проверки остались.

## Развёртывание

1. Подготовьте отдельный Supabase для приёмки. Для пустого проекта примените
   `supabase/migrations/001_households.sql` администратором в транзакции.
   Для существующего бюджета используйте [процедуру переноса](docs/ARCHITECTURE.md#миграция-старой-семьи).
   В `index.html` задайте URL и публичный ключ проекта. В Supabase настройте
   подтверждение email и адрес возврата Auth для тестового домена.
2. Пройдите приёмку из [чек-листа выпуска](docs/RELEASE_REVIEW.md#чек-лист-выпуска).
   Для рабочего перехода сделайте внешний backup и подтвердите его восстановление.
   Новая корневая страница и семейная SQL-схема выпускаются вместе в окно обслуживания.
3. В Settings → Pages → Build and deployment переключите Source на **GitHub Actions**.
   Workflow `.github/workflows/pages.yml` публикует артефакт после успешных
   проверок при push в `master` либо ручном запуске для `master`.
   Pull request и push в `codex/budget-release` запускают проверки без публикации.
   `npm run package:pages` локально собирает
   `_site/` по списку публичных файлов из `tests/package-pages.cjs`.

По последней проверке 23.11.2026 Pages использует `master:/` (`build_type: legacy`).
В этом режиме GitHub публикует ветку независимо от нового workflow.
Переключение Pages, изменение рабочей БД и публикация остаются отдельным выпуском.

## Восстановление

- **Локальные данные.** В настройках выберите «Восстановить из файла» и укажите
  внешний JSON. Импорт заменяет текущие данные. Вернуться к состоянию до импорта
  можно в том же браузере, пока его хранилище доступно. Для переноса на другой
  адрес или устройство сохраните и перенесите внешний файл.
  [Совместимость копий](docs/ARCHITECTURE.md#копии-и-офлайн).
- **Облачные данные.** Пока транзакция переноса открыта, выполните откат по процедуре
  миграции. После фиксации переноса сохраните новые записи отдельно, восстановите
  проверенную копию БД в изолированном проекте и переключите frontend на совместимую
  схему. [Backup, перенос и откат](docs/ARCHITECTURE.md#миграция-старой-семьи).
